# C5 — окончательная приёмка V4

**Решение: V4 остаётся исследовательской моделью. Основная V1 сохраняется; поиск новых конфигураций остановить.** Это независимая проверка выгрузки, а не повтор сообщения C2. Обе заранее зафиксированные проверки допуска V4 не пройдены; пороги не пересматривались.

## Что проверено

- ZIP5707082bytes, SHA256 `908498c58a3c41d913a0258565e5f3c507200a2da5bd031373668de5cea3b67e`; все62 файла совпадают с извлечёнными.
- Runtime code SHA точно совпадает с frozen `87de433`, протоколом `dcb7c13` и поправками, включая обе curve-reference и insufficient evidence для малого required slice. Код и данные не подменены после результатов.
- Неизменный NPZ: `b4d01f11d33d485c1a36940b849ba345300698fa306ac98ffcb25749d5458dc0`; его features и labels уже независимо сверены C5 с C1/440NWP в первом аудите.
- 36нейронных checkpoint,12CatBoost моделей,12CSV,13842прогнозных строк,820наборов slice/model RMSE/MAE/bias/n. Все SHA и арифметика проверены заново. Февральские и январские targets отсутствуют.
- Шесть фиксированных chronological folds на каждой турбине; scaler, full/recent91-day curves, train-derived power/ramp thresholds независимо пересчитаны. Target overlap между train/validation отсутствует.
- Повторный inference из36сохранённых MLP на CPU: максимум разницы с CUDA1.4156103134e-7;12CatBoost воспроизводятся на CPU точно. Это сравнение разных устройств, а не требование побитовой идентичности.
- Среднее трёх seeds, применение alpha, метрики уникальных target-hour с усреднёнными прогнозами, bootstrap и итоговые gates пересчитаны. В bootstrap-folds нет пропущенных календарных дней. Ни одного нового обучения или обращения к GPU не было.

## Результат и причины отказа

| Средний RMSE шести folds | T1 | T2 |
|---|---:|---:|
| Full-history curve |.25537752|.25368547|
| Recent91-day curve |.25661942|.25593194|
| Fixed GPU CatBoost |.25042769|.25603598|
| Raw MLP |.24976442|.24969815|
| Shrinkage MLP |**.24889839**|**.24910720**|

Point improvement shrinkage против full curve: примерно2.54%/1.80%. Это полезный исследовательский результат, но не достаточное основание для production замены.

- **T1:** менее2% улучшения против CatBoost; December1 bias хуже recent91-reference более.01; December15 high-wind RMSE хуже full curve более5%; верхняя граница описательного интервала положительна.
- **T2:** менее2% улучшения против full curve; March high-wind хуже обеих curves более5%; несколько March/June/December bias-ограничений нарушены; интервал включает0.
- Bootstrap95% shrinkage-minus-fullcurve: T1[-.0125366103,+.0001011943], T2[-.0101257872,+.0015041122]. Знак интервала нельзя округлить до желаемого PASS.

2%,5%,.01 и min100pairs — внутренние инженерные критерии, заранее согласованные для этого цикла. Это не норматив организатора, не отраслевой benchmark и не доказанный бизнес-порог. Уже просмотренные folds не становятся независимым test при добавлении методов; интервалы не скорректированы на многократный исследовательский выбор.

## Граница проверки alpha и CUDA

Frozen source корректно считает alpha только на inner-stop после реконструкции модели inner-fit ровно на selected epoch. Независимо подтверждены inner-mask counts, выбранные epochs из stopping-history, диапазон alpha[0,1], совпадение alpha между report/checkpoint и применение коэффициента к прогнозам. **Inner calibration predictions/weights не экспортированы**, поэтому численную оптимальность самого alpha нельзя независимо восстановить без дополнительного обучения. Такое обучение не запускалось; эта часть является source/protocol inspection, а не полной численной репликацией калибровки. Она не меняет отказ в promotion.

Дополнительно найден локальный C2 JSON `hackalem-cuda-restore.json`:24веса V3, same-CUDA max error0.0, TeslaT4. Файл прочитан, SHA сохранён в `v4-recomputed.json`. Это измерение C2, **не самостоятельный запуск C5 на CUDA**; маленький JSON не привязывает результат к отдельным SHA весов. Исходное CPU/CUDA расхождение Transformer3.4362e-5 остаётся честно отражённым в первом дополнении.

## Действие команды

V1 `nwp-tabular-7f1b4f31e9bb` остаётся production. V4 evaluation weights хранить отдельно; автоматически не подключать через MODEL_DIR. Дальнейшая работа — сохранение артефактов, выключение вычислений владельцем C2, чистый запуск, устойчивость API/агента, README и согласование исторической доступности погоды/SCADA timezone. Не менять пороги, seeds или модель, чтобы добиться красивого отчёта.

Воспроизведение из корня worktree, существующий optional research Python:

```powershell
<C2-python> docs/verification/model-quality/audit_v4.py --c2-root <C2-worktree> --output docs/verification/model-quality/v4-recomputed.json
```

Команда читает существующие данные, не обучает и не использует облако. Агрегированное свидетельство: `v4-recomputed.json`. Историческое `run+9h` и UTC+6 по-прежнему неподтверждённые допущения; более сложное обучение их не устраняет.
