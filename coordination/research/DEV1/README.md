## Критические ловушки

1. **Утечка через архив.** Historical-Forecast склеен из упреждений 0–5 ч (почти анализ) — как вход теста это утечка. `previous_dayN` утекает частично (см. R04). Реанализ (ERA5, NASA POWER) — только факт, не прогноз.
2. **Задержки публикации прогона 00Z** (из `meta.json`): ECMWF 9 км ≈7.0 ч, ECMWF 0.25° ≈7.8 ч, AIFS ≈5.7 ч, GFS ≈5.5–6.5 ч, ICON ≈3.7 ч, UKMO ≈8.4 ч.
3. **Архив может исчезнуть.** Open-Meteo уже удалял прогоны (#1969); бакет S3 хранит прогоны ≈3 месяца. Нужные для февраля ответы стоит закэшировать и приложить к репозиторию, чтобы эксперты могли повторить расчёт (лицензия CC BY 4.0 — нужна атрибуция).
4. **Тихие ошибки API.** Неподдерживаемая переменная или модель возвращает HTTP 200 с пустыми значениями и единицей `"undefined"`; `best_match` падает, если нет хотя бы одного компонентного прогона. Проверять долю непустых значений, а не только код ответа. Всегда указывать модель явно.
5. **Лимиты бесплатного Open-Meteo:** 600/мин, 5 000/ч, 10 000/сутки; запрос с более чем 10 переменными или периодом больше 2 недель считается за несколько вызовов; один параллельный запрос с IP. Бесплатный уровень — только некоммерческое использование.
6. **Откат pandas.** skforecast, statsforecast, mlforecast, OpenOA и brightwind при установке понижают pandas 3.0.6 до 2.3.3 (OpenOA ещё и scikit-learn до 1.6.1); autogluon.timeseries требует pandas < 2.4 и тянет PyTorch. Чисто ставятся: xgboost, catboost, statsmodels, optuna, shap, MAPIE 1.x, sktime, darts, openmeteo-requests, herbie-data, ecmwf-opendata, eccodes/cfgrib, meteostat, metpy, windpowerlib.
7. **pandas 3:** частоты `'H'`, `'T'`, `'S'`, `'M'` вызывают ошибку (нужны `'h'`, `'min'`, `'s'`, `'ME'`); по умолчанию точность дат — микросекунды; присваивание цепочкой (`df['a'][i] = ...`) молча ничего не делает; `fillna(method=)` удалён.
8. **Meteostat для станции 36894:** все строки 2026 года — прогноз модели MET Norway, а не наблюдения. Фильтровать по `wspd_source`.
9. **litellm 1.82.7 и 1.82.8 были вредоносными** (атака на PyPI 24.03.2026) — версии фиксировать точно.
10. **GitHub Models закрыт 30.07.2026**; бесплатные облачные LLM требуют личного аккаунта. Без чужих ключей работают только локальные модели (Ollama) или детерминированный режим без LLM.

## Прочие опорные факты

- **Реалистичная точность на сутки вперёд:** одиночные ВЭС — NMAE 10–16 %, NRMSE 15–21 % от мощности; для 2 турбин оценка NMAE 10–18 %. **NMAE < 8 % — повод искать утечку.**
- **Победители NWP-соревнований** (GEFCom2012/2014, HEFTcom2024) — градиентный бустинг на признаках прогноза погоды: ветер на 100 м со сдвигами ±часы, сглаживание, отдельная модель на каждый источник погоды с последующим блендингом.
- **Альтернативные архивы без ключа на февраль 2026:** GFS 0.25° (`noaa-gfs-bdp-pds`, `global-forecast-system`) с 100 м ветром, ECMWF open data IFS/AIFS 0.25° (GCS `ecmwf-open-data`; `100u`/`100v` у IFS примерно с 04.2024), GraphCast-GFS на AWS (01.2025–05.2026).
- **Ближайшие станции:** WMO 36894 (≈21–24 км; источники расходятся — «Шелек» или Малыбай, 870 м) и 36891 «Чилик». В GHCNh на 2026 год данные есть с шагом 3 ч; ISD остановлен в 2025.
- **Ценность для бизнеса:** дисбалансы ВИЭ обошлись Единому закупщику ≈7.55 млрд тг в 2024 году. Для договоров после 01.07.2023 недобор оплачивается по 1.3× цены, излишек — по 0.7×. Samruk-Energy 20.08.2026 анонсировал собственную ИИ-систему прогнозирования (владелец предполагаемой площадки).
