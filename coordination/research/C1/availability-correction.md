# R03: исправление доступности ECMWF IFS

Проверка C1 23.09.2026 около 14:31 Asia/Qyzylorda. Источники: [официальная Single Runs API](https://open-meteo.com/en/docs/single-runs-api), [Model Updates и metadata API](https://open-meteo.com/en/docs/model-updates), живой ответ [metadata ecmwf_ifs](https://api.open-meteo.com/data/ecmwf_ifs/static/meta.json). Последний запрашивается обычным GET; в проверке Python urllib/json прочёл поля last_run_initialisation_time и last_run_availability_time.

Наблюдение в ответе: last_run_initialisation_time = 1790121600 (2026-09-23 00:00:00Z), last_run_availability_time = 1790146822 (07:00:22Z), лаг **7 ч 00 мин 22 с**. Поставщик определяет второе поле как момент фактической доступности на API и рекомендует добавить ещё 10 минут из-за нескольких серверов. Следовательно, прежнее run+6h **не было консервативным**: допустило бы 00Z прогон с 06:00Z, когда этот проверенный текущий выпуск ещё не был доступен.

Исправление C1: available_at = run_init + 9h, availability_basis = inferred_run_plus_9h, provenance_status = unconfirmed. Это операционный запас на фоне текущего наблюдения, **не подтверждённое историческое время публикации и не гарантия отсутствия утечек**. Метаданные доступны только для последнего текущего прогона; для архивного выпуска 2026-01-31 00Z точная публикация в нём не сохранена. Тест отвергает выпуск в 06:00/08:00Z и принимает покрытый 48-часовой горизонт с issue 12:00Z на 72-часовом fixture. Для статуса verified as-issued нужен исторический журнал публикации или другой первичный источник с per-run временем; пока историческое воспроизведение должно быть помечено conditional.

Карточки Claude (9826232) пригодны как каталог источников. Уточнение по [Previous Runs](https://open-meteo.com/en/docs/previous-runs-api): суффикс previous_day1/2 фиксирует lead от valid time, а не один выпуск на 24/48 ч; поздние часы горизонта могут происходить из прогонов после issue time. Для P0 использовать Single Runs с явным run/init и issue gate, сохраняя статус неопределённости. [Historical Forecast](https://open-meteo.com/en/docs/historical-forecast-api) склеивает первые часы разных прогонов и не является заменой 24–48-часового выпуска. Бесплатный Open-Meteo согласно [условиям](https://open-meteo.com/en/terms) предназначен для некоммерческого использования и имеет лимиты 600/мин, 5000/час, 10000/сутки; три малых пробных запроса ниже них.
