# C1: независимые идеи по данным и погоде

Основание: `coordination/research/C1/evidence.md` (`1bc29c1`); идеи ниже — предложения, не проверенные результаты модели. Оценка минут включает интеграцию и проверку. Новые API, обучение и GPU в рамках совета не запускаю.

- ID C1-01 | Gate доступности погоды | Для каждой записи NWP хранить `run_init`, консервативный `available_at=run_init+6h`, `issue_time`, `valid_time`; отвергать `available_at>issue_time` | исключена явная временная утечка | unit check на 00Z при issue 00Z (reject) и issue 07Z (accept) | 25+10 | C1 | фактическая задержка публикации неизвестна; +6h — консервативное правило.
- ID C1-02 | Манифест происхождения | В export рядом с прогнозом записывать модель, URL/параметры, run, время запроса, SHA ответа, число `null` и покрытие | результат воспроизводим и аудируем | повторный запуск показывает тот же манифест при кэше | 25+10 | C1 | live API может изменить ответ; сохранять версию ответа.
- ID C1-03 | Проверка 24/48 часов | Валидировать ровно 24 либо 48 последовательных `valid_time` после выпуска, без `null`/дубликатов и пропусков | неполные выпуски явно остановлены | тест пропуска одного часа блокирует экспорт | 15+10 | C1 | архивные запуски иногда покрывают меньше часов.
- ID C1-04 | Одна погодная ячейка, две турбины | Запрашивать NWP один раз по общей сеточной ячейке и подавать общие погодные признаки в две отдельные ветки прогноза | меньше сетевых запросов и согласованные метеовходы | проверка идентичности gridpoint и один запрос на выпуск | 20+10 | C1/C2 | если gridpoint изменится, перейти на два запроса.
- ID C1-05 | Чувствительность UTC | Конфигурируемый сдвиг SCADA UTC+5/+6/+7; сравнить на январских доступных данных, без февральских меток | явная оценка риска неверного времени | таблица качества/совпадений для трёх сдвигов и выбранное правило | 25+15 | C1/C2 | метаданные SCADA отсутствуют; корреляция не доказывает часовой пояс.
- ID C1-06 | Разрывы SCADA | Сформировать маску часов без достаточного числа 10-минутных наблюдений и исключить их из обучения/проверки | модель не обучается на фиктивно заполненных часах | тест на известном разрыве мая–июля 2024 отвергает эти часы | 20+10 | C1 | порог достаточности надо согласовать с C2.
- ID C1-07 | Freeze по issue time | В симуляции выпуска доступными считать только записи SCADA `timestamp<=issue_time` с явным преобразованием часового пояса | нет поздних фактических лагов, включая 31 января | тест поздней строки 31.01 не попадает в выпуск 31.01 00Z | 20+10 | C1 | выбор issue schedule зависит от доступности погоды.
- ID C1-08 | Статус пригодности источника | Сначала маленький source-probe: 3 исторических run, 24/48-часовое покрытие, null, gridpoint, время публикации и SHA; выдать PASS/CONDITIONAL/FAIL | понятный go/no-go перед интеграцией погоды | артефакт с URL, командами и конкретными проверками | 25+10 | C1 | HTTP 200 не подтверждает историческую публикацию; при FAIL нужен честный fallback.
- ID C1-09 | Явный fallback при отсутствии NWP | При недоступности исторически допустимого выпуска использовать простой прогноз по разрешённым прошлым данным и помечать `source=fallback` | приложение выдаёт результат без скрытой подмены реанализом | искусственно отключённая NWP ветка формирует 24/48 ч и метку | 20+15 | C2/C1 | качество может быть слабым; не заявлять выигрыш без оценки.
- ID C1-10 | QC нормализованной мощности | Проверять диапазон/выбросы, долю нулей и объём доступных пар по двум турбинам без домысливания кВт или МВт | прозрачная целевая переменная и ошибки данных | отчёт по диапазону и списку отфильтрованных часов | 20+10 | C1 | истинная номинальная мощность неизвестна.
